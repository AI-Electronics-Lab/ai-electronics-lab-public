# Publication Checklist

Status: draft  
Last updated: 2026-06-09

Use this checklist before changing repository visibility, publishing public-facing content, linking public examples, or reusing text on social/media channels.

## Repository and page visibility

- [ ] Repository visibility is intentional.
- [ ] Human approval is recorded before major public positioning changes.
- [ ] Public site link is correct: `https://ai-electronics-lab.pages.dev`.
- [ ] Public demo app access details are listed only if intentionally approved for public prototype access.
- [ ] Protected app access does not expose administration, internal operations, private data, or privileged functionality.
- [ ] Public demo links point only to approved public pages.

## Content safety

- [ ] No secrets or private credentials.
- [ ] No internal hostnames.
- [ ] No private operational paths.
- [ ] No private runbook details.
- [ ] No unapproved screenshots.
- [ ] No private artifact paths.
- [ ] No private evidence packets.
- [ ] No raw internal logs.
- [ ] Public demo credentials, if present, are intentionally approved and scoped for public prototype access only.

## Claim safety

- [ ] Current capability, limitation, roadmap, and speculation are separated.
- [ ] Technical claims are listed.
- [ ] Claims about circuits, SPICE, calculation, units, safety, or hardware behavior are technically reviewed where required.
- [ ] Simulation is not described as hardware proof.
- [ ] AI is not described as replacing engineers.
- [ ] CAD/EDA replacement claims are avoided unless explicitly approved.
- [ ] Limitations are visible near relevant product claims.

## Public example safety

- [ ] Example has a clear user goal.
- [ ] Example has visible assumptions.
- [ ] Example has caveats.
- [ ] Example status is clear: current capability, demo, roadmap, or proposal.
- [ ] Example artifacts are approved for publication.
- [ ] No private artifact paths are included.
- [ ] Links render correctly.

## Channel consistency

- [ ] GitHub, public site, Hackaday, and LinkedIn tell the same core story.
- [ ] GitHub acts as the evidence/documentation layer.
- [ ] Hackaday acts as the engineering build log.
- [ ] LinkedIn acts as the professional story layer.
- [ ] Facebook/Telegram content remains personal/backstage and avoids unsupported claims.

## QA checks

- [ ] Markdown renders correctly.
- [ ] Links are valid.
- [ ] Tables render correctly.
- [ ] No broken relative links.
- [ ] No accidental private references.
- [ ] Public site URL is prominent in the README.
- [ ] Public beta app access, if present, is visible near the top of the README and repeated in FAQ.

## Final approval

- [ ] Human publication approval is explicitly recorded.
- [ ] Publication scope is exact.
- [ ] Remaining risks are listed.
- [ ] Follow-up tasks are recorded if needed.
