# Public Claim Review Checklist

Status: draft.

Use this checklist before publishing public-facing content.

## Claim classification

For each meaningful public claim, classify it as one of:

- Current capability
- Known limitation
- Roadmap / future work
- Speculation / proposal
- Product principle
- Community/narrative statement

## Technical review required

Technical review is required for claims about:

- electronics correctness;
- SPICE behavior;
- schematic validity;
- calculation accuracy;
- units and tolerances;
- safety;
- hardware validity;
- production readiness;
- physical performance.

## Safer wording pattern

Prefer:

```text
AI Electronics Lab helps explore <workflow> and produce <artifact/evidence> with caveats.
```

Avoid:

```text
AI Electronics Lab guarantees <hardware/design/safety/correctness>.
```

## Review record

For each public document, record:

- document path;
- claim summary;
- classification;
- Technical review needed: yes/no;
- UX review needed: yes/no;
- QA check needed: yes/no;
- Human publication approval: pending/approved/not requested.
